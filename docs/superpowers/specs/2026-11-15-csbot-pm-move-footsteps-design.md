## Approach
Observe actual PM_PlaySound calls within pre/post PM_Move via a bounded adapter-owned callback stack. The existing global EmitSound hook cannot see engine-internal movement sound. Inferring footsteps from alternating-step/timer fields is rejected: runfuncs/footsteps disabled and skipped wading can advance fields without a sound. Do not synthesize GameDLL animation events or copy PM physics.

The bridge temporarily installs a non-exported public-signature thunk, forwarding every original call exactly once with all arguments unchanged, including non-footsteps/STOP/invalid AI observations. Track bounded8 scopes, handle same/different-move nesting and unwrap our own thunk for forwarding while restoring the original scoped callback. Over-limit scopes suppress capture but preserve audio. Post restores only fields still owned by us; foreign replacements remain untouched. Unmatched post fails closed and unwinds owned scopes. Capture is suspended during forwarding to prevent recursive attribution; nested PM scopes remain supported. Map/round reset restores owned callbacks and cancels capture; detach while any scope/forwarding call is active is rejected until unwind, preventing a live thunk from being unloaded.

Only server argument, runfuncs, current map/round, valid alive nonspectator client slot and serial identity permit intake; serial0 is valid. Source identity is captured at pre and revalidated at sound time, no hidden enemy identity. Capture live pmove.origin, validate finite/bounded coordinates, do not mutate edict origin. Known standard material steps alone feed existing Low/1100 footstep path, NAV memory/look/investigation/chatter and raw<300 sniper equipment. Original audio runs for rejected observations. Same scoped EmitSound duplicate uses the same live movement origin so existing event-ID dedup applies. No new per-frame world scan/RNG stream/private offset/export.
