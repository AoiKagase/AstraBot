# P12：ZBot相当の移動能力と地形検証による拡張

## 1. 目標と基本方針

**ZBot相当を最低必須要件とし、その上に人間的な近道選択を追加する。** ZBotとの実装差ではなく、同一地形・物理条件での通行能力を評価する。

- 必須能力：安定した経路追従、階段、しゃがみ、Jump／Drop、細道、梯子、扉、BOT回避、停止からの復帰。
- 拡張能力：壁沿いの細道、既存NAVに接続のない近傍領域間の移動、軽傷を許容した飛び降り。
- ZBot基礎能力と独自拡張は別々に受け入れる。拡張の成功で基礎能力の未達を相殺しない。
- 今回はNav／移動を対象とする。購入・戦術の拡張は含めず、既存Combatの照準・射撃・ラウンド復帰を回帰確認する。
- ZBot参照元はReGameDLL_CS `b0889847`。参照先と挙動差を記録し、ソースの転用はライセンス確認なしに行わない。

## 2. 実装順序

### 段階A：現在の停止・往復原因を修正

通行範囲を広げる前に、既存経路の実行を安定させる。

- Walk／Jump／Dropの実効移動種別を分類・計画・実行・dispatchで統一する。元の属性との二重判定による拒否を解消する。
- portalへの誘導、横方向の回避、距離制限の順序を整理する。最終移動先に距離上限を適用し、補正による`BudgetExceeded`を防ぐ。
- 正常に進行中のゴールを、他BOTの予約だけでは取り消さない。新規ゴール選択と現在ゴールの有効性判定を分離する。
- 混雑予約を現在stepからの未通過区間に限定する。通過・停止・死亡・経路変更時に解放し、逆方向からの進入も混雑判定へ含める。
- 観測不足・予算不足・鮮度切れ・プレイヤー衝突は一時失敗とする。NAV世代内の辺除外は、静的な通行不能が検証された場合だけに限定する。

### 段階B：ZBot相当の局所移動を成立させる

- NAV境界は案内情報として扱い、物理的な壁とは区別する。狭いportalを許可した後で、NAV内へのhull完全内包を再要求しない。
- 実hullの衝突検査と、エンジンの接地判定に対応した床支持検査で通行可否を決める。単一点の床ヒットだけで安全とは判断しない。
- 歩行衝突時は、次の床サンプルが同じ高さでもstep-up検査を行う。持ち上げ・前進・着地を検証し、通常階段をJump頼みにしない。
- step-upで越えられない段差は、実際の前方地形からJump候補を作る。上昇可能高さは重力・跳躍力・姿勢から導き、分類側80／実行側32の不一致を廃止する。
- `NAV_PRECISE`は通行禁止ではなく、横方向補正を抑えた精密追従として扱う。しゃがみ・Jump属性は対応する姿勢遷移で処理し、`NO_JUMP`は尊重する。
- プレイヤー障害物では、検証済みの横避け、期限付き譲り合い、再探索を使う。actorの待機時間と安定した優先順位で双方が永久停止することを防ぐ。
- 狭い通路と特殊移動の踏切・着地点は短期予約する。近距離の押し合いを、経路コストの増加だけで解決しない。
- 梯子・扉の既存処理もZBot比較対象に含め、経路継続と失敗復帰の欠落を修正する。

### 段階C：NAVにない近道を追加

既存NAVと、実行時の追加接続を合成した検索グラフを導入する。

- 近傍領域の境界からWalk／Jump／Drop候補を生成する。領域中心同士を単純に直線接続しない。
- 候補はhull通過、床支持、踏切、飛行中の衝突、着地、着地後の経路継続を検証してから検索対象へ追加する。
- 細道は壁沿いの複数の通行点を保持できるようにする。直線一回の検査が通らないことだけで、折れ曲がった細道を拒否しない。
- 接続は有向とし、逆方向は別途検証する。既存NAV接続と同じ検索・実行・失敗通知経路を使う。
- 候補探索の初期水平範囲は256単位とする。高さは固定128ではなく、Jump能力と許容落下リスクから絞る。
- 追加探索は全actorの通常更新後に実行する。初期上限は全体で8 world query／フレーム、actor当たり候補8件、追加接続128件。不足時は次フレームへ持ち越し、通常の移動・戦闘予算を奪わない。
- 接続上限では未使用・古い候補から破棄する。使用中接続は保持し、検証できない場合は既存NAV経路へ戻す。

### 段階D：損傷と時間を考慮して近道を選択

- 経路コストを予測所要時間を基準に統一し、混雑待ち・特殊移動準備・失敗リスク・落下損傷を加える。現在の固定8192加算は置き換える。
- 軽傷の初期定義は「予測損傷が10HP以下かつ現在体力の10％以下、着地後30HP以上」とする。
- 損傷ありの近道は、安全経路より予測到着が1秒以上早い場合だけ候補にする。損傷1HPにつき0.1秒相当の追加コストを課す。
- 落下損傷は現行ReGameDLLの落下速度ベースの式と物理観測から予測する。不明な独自物理や予測と実測の不一致がある場合、損傷ありDropを無効化する。
- 飛び降り直前に体力・着地点・障害物を再確認する。着地観測が成立するまで経路stepを進めない。直接velocityは書き換えない。

## 3. 内部インターフェースと診断

公開6 exportとNAVファイル形式は変更しない。

- 既存経路と追加接続を列挙できる内部グラフ参照層を設け、検索とCorridor構築の双方で使用する。
- 通行計画には、接続識別子、実効移動種別、通行点、必要姿勢、予測時間・損傷、検証世代を保持する。
- 地形検証はmap／NAV／物理条件に結び付ける。実行ticketはactor／round／route／stepにも結び付け、死亡・再spawn・削除・edict再利用で無効化する。
- 追加接続はmap／NAV変更で破棄する。ラウンド変更では予約と実行状態を破棄し、地形候補は再検証するまで使用しない。
- ログは状態変化と上限付き集計を中心に、通行種別、実際の失敗辺、失敗分類、待機理由、予約所有者、進捗、予測／実測損傷を記録する。

## 4. 回帰テストと実機受入れ

テストソースは実装と併せて追加するが、**明示的な実機PASS前はテスト用configure・ビルド・実行、CTest、canonicalを行わない。**

回帰対象は以下とする。

- Walkから変換したJump、属性付きJump、能力上限、`NO_JUMP`、しゃがみ・精密通行。
- portal補正後の距離上限、狭い重なり、同じ床高さでの階段衝突。
- 現在ゴール保持、実行stepに追従した予約、対向BOTの譲り合い。
- 一時失敗後の再試行、恒久除外の限定、actor間の更新公平性。
- 追加接続の検索・実行・無効化、予算不足、体力変化、危険な着地点の拒否。

実機は次の順序で行う。

1. **比較記録**：まず`de_dust`で、同じNAV・開始地点・ゴール・物理条件のZBot通行記録を作る。重点辺`5→70`、`5→1665`、`2036→141`に加え、階段・細道・扉・梯子を適切な場所で確認する。
2. **基礎能力**：ZBotが通過できる比較ケースをAstraBotが各5回連続で完了する。構造的な通行不能と、BOT接触による一時待機を区別する。
3. **複数BOT**：2対2、続いて設定BOT数で10分以上・3ラウンド以上確認する。全actorで進捗と失敗復帰を記録し、押し合い・無理由停止・不要なゴール反転が残らないことを確認する。
4. **独自拡張**：壁沿いの細道、非接続Jump／Drop、軽傷を伴う近道を基礎能力とは別に確認する。安全条件を満たさない経路の拒否も受入れ対象とする。
5. **遷移・戦闘回帰**：死亡、次ラウンド、追加削除、map変更、edict再利用、照準・射撃・ダメージを確認する。

比較ケースのPASSを全マップ互換とは呼ばず、マップ・NAV・条件ごとに結果を残す。基礎能力の未達は必須不具合として扱う。
