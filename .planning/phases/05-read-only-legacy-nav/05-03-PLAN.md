<objective>
Publish validated Nav documents as immutable snapshots and define map/source
fingerprint checks without coupling Nav state to actor or AstraNav state.
</objective>

<context>
Read `05-CONTEXT.md`, `05-02-PLAN.md`, lifecycle generation contracts, and
the design rule that map/round/actor generations must remain explicit. The
snapshot must be safe to invalidate on map change and must never write Nav.
</context>

<tasks>

### Task 1: Write failing snapshot/fingerprint tests

Test publish/retrieve/invalidate, failed replacement preserving the previous
snapshot, map-name normalization, BSP-size mismatch, source hash mismatch,
and generation/revision changes across map activation.

### Task 2: Implement immutable publication

Add a value/const snapshot handle with explicit revision and source identity.
Use a transactional publisher that exposes only const Nav data after
validation. Add bounded map fingerprint input and explicit match/mismatch
results; do not mix current hidden world or actor state into Nav identity.

### Task 3: Verify invalidation and extension boundary

Run snapshot/fingerprint tests and existing lifecycle tests. Confirm the
interface leaves a codec/authoring boundary for future AstraNav and has no
write path for legacy `.nav`.

</tasks>

<must_haves>

- Readers cannot expose a partially validated document.
- Map/source mismatch is explicit and fail-closed for runtime publication.
- Snapshot data is immutable to consumers and independently revisioned.

</must_haves>

<verification>

1. Observe snapshot tests fail before implementation.
2. Run all x86 Core tests and lifecycle tests.
3. Check C++ format, SDK-free Core headers, and no Nav writes.
</verification>
