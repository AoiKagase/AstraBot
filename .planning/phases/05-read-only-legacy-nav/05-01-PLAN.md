<objective>
Define the bounded, format-neutral Nav value model and validation limits that
legacy readers can publish without exposing file-layout or SDK types.
</objective>

<context>
Read `05-CONTEXT.md`, the design contract, Phase 4 summaries, and the pinned
legacy format reference. Keep the model independent of file I/O and future
AstraNav authoring.
</context>

<tasks>

### Task 1: Write failing Nav model tests

Test valid area geometry, directed connections, v1-v5-normalized hiding spots,
place records, encounters, duplicate IDs, degenerate extents, non-finite
coordinates, invalid references, and named count limits.

### Task 2: Implement value model and validation

Add SDK-free `NavDocument`, `NavArea`, `NavConnection`, `NavHidingSpot`,
`NavEncounter`, `NavPlace`, `NavSourceIdentity`, and `NavLimits`. Use bounded
containers and explicit validation results. Keep file version details outside
the public model.

### Task 3: Verify model boundaries

Run Core tests and confirm no Nav header includes HLSDK/GameDLL types. Check
copy/move and snapshot handoff behavior without adding runtime integration.

</tasks>

<must_haves>

- The model represents stable area IDs, geometry, directed connectivity, and
  normalized legacy metadata.
- Invalid values cannot enter a document through public model operations.
- No Core Nav contract exposes legacy file layout or SDK pointers.

</must_haves>

<verification>

1. Observe Nav model tests fail before the model exists.
2. Run Windows/Linux x86 portable Core tests.
3. Run source-format and SDK-boundary checks.
</verification>
