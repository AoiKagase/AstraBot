<objective>
Implement a bounded byte reader for legacy `.nav` versions 1 through 5 and
normalize every accepted version into the Phase 5 Nav model.
</objective>

<context>
Read `05-CONTEXT.md`, `05-01-PLAN.md`, and the pinned ReGameDLL-CS load
layout. Do not import or reproduce `CNavArea`, `PlaceDirectory`, or
`LoadNavigationMap` implementation structure.
</context>

<tasks>

### Task 1: Write failing version and corruption fixtures

Create synthetic little-endian fixtures for v1, v2, v3, v4, and v5. Cover
truncated headers/areas, bad magic/version, zero/oversized counts, duplicate
area IDs, invalid connection targets, bad place lengths, non-finite floats,
degenerate extents, and trailing/incomplete encounter data.

### Task 2: Implement bounded reader

Use a cursor with checked `readU8/readU16/readU32/readFloat/readBytes`
operations. Validate bounds before reserve/loop, decode version-specific
sections, retain source identity metadata, and publish only after all area
references resolve. Return explicit `NavReadResult` values.

### Task 3: Verify transactional and version behavior

Run focused reader tests through RED/GREEN/refactor, then all prior x86 Core
tests. Confirm the input byte array is unchanged and a failed read does not
replace an existing document.

</tasks>

<must_haves>

- All supported versions 1 through 5 consume the correct legacy sections.
- Allocation and loop bounds are checked before use.
- Corrupt input fails closed without a partial document.

</must_haves>

<verification>

1. Observe missing-reader RED before production code.
2. Run reader and full portable x86 tests on Windows/Linux.
3. Check no ReGameDLL source or private symbol is linked.
</verification>
