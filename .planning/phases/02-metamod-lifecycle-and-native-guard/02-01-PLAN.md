<objective>
Turn the Phase 1 export shell into a real Metamod-P plugin entrypoint that
publishes only the lifecycle hook tables, validates every ABI input, and
keeps all callback state in one adapter-owned context.
</objective>

<context>
Read `02-CONTEXT.md`, the Phase 1 ABI plans and summaries, `AGENTS.md`,
`C_CPP_REFACTOR_RULES.md`, the approved design, and the pinned
`metamod-p/stub_plugin` hook-table examples. Use the SDK headers by include
path. Preserve the six existing exports and their calling conventions.
Do not create a FakeClient, invoke a private GameDLL symbol, or add
compatibility commands in this plan.
</context>

<tasks>

### Task 1: Write the failing hook-table contract test

**Type:** test
**Files:** `tests/metamod_hook_table_tests.cpp`, `CMakeLists.txt`

**Action:** Add a host-side C++ test that calls the exported ABI functions
with the SDK-declared types. Assert that `Meta_Attach` rejects null tables,
that a valid attach publishes `pfnGetEntityAPI2` and
`pfnGetEngineFunctions`, and that those callbacks accept the expected
interface versions. Assert that the returned `DLL_FUNCTIONS` contains the
five lifecycle callbacks used by this phase and that an empty/invalid input
does not mutate a caller-owned table. Add the test target and CTest entry.

**Verify:** Configure and build the test target before implementing the new
runtime/context code. It must fail for the missing callback implementation,
not because of a malformed fixture or an SDK include problem.

**Acceptance criteria:** The test describes the public hook contract and is
observably red before production changes.

### Task 2: Implement the adapter-owned plugin context and hooks

**Type:** implementation
**Files:** `include/astrabot/metamod/abi_contract.hpp`,
`src/adapter/metamod/plugin_runtime.hpp`,
`src/adapter/metamod/plugin_runtime.cpp`,
`src/adapter/metamod/plugin_exports.cpp`

**Action:** Introduce a small `PluginRuntime` context with explicit states
for cold, attached, active-map, and detached operation. Store Metamod
utility/global pointers only after successful validation. Populate
`META_FUNCTIONS` with the project callbacks for `GetEntityAPI2` and
`GetEngineFunctions`; leave unsupported post/new-DLL hooks null. Populate a
`DLL_FUNCTIONS` table with `ClientDisconnect`, `ClientPutInServer`,
`ServerActivate`, `ServerDeactivate`, and `StartFrame` callbacks. Populate
the engine table only with hooks implemented in this phase. Every callback
must set the Metamod result through the public API and return without
throwing. `Meta_Detach` must invalidate the context before returning.

Keep the existing metadata/export names unchanged. Keep `GiveFnptrsToDll`
as an ABI-safe bootstrap no-op unless the runtime can safely record the
pointer without taking ownership. Do not call an SDK function merely to make
the shell appear active.

**Verify:** Re-run the focused hook-table test and the existing ABI test on
Windows x86 and Linux x86. The result must be green with warnings treated as
errors.

**Acceptance criteria:** A valid Metamod attach publishes the expected
pre-hook table, invalid versions fail closed, and detach makes subsequent
lifecycle callbacks harmless.

### Task 3: Refactor and record the adapter boundary

**Type:** refactor
**Files:** the files changed by Tasks 1-2

**Action:** Remove duplicated global lifecycle decisions from
`plugin_exports.cpp`, use the new context as the single owner, and document
why SDK callbacks remain in the adapter. Apply
`C_CPP_REFACTOR_RULES.md`: Allman braces, real-tab indentation, LF,
UTF-8 without BOM, one statement per line, named constants for nontrivial
limits, explicit null/error handling, and no accidental ABI changes.

**Verify:** Run the focused CTest case, `git diff --check`, and a targeted
source-format check for the new/changed C++ files. Confirm no reference or
SDK file was copied or modified.

**Acceptance criteria:** The hook table has one clear ownership path and
existing Phase 1 exports remain exact.

</tasks>
