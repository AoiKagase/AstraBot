<objective>
Prevent native ReGameDLL-CS CSBot ownership from silently mixing with
AstraBot by constraining public bot controls, blocking native registrations,
and detecting unmanaged FakeClients with an explicit fail-closed result.
</objective>

<context>
Read `02-CONTEXT.md`, `02-01-SUMMARY.md`, `02-02-SUMMARY.md`, the pinned
Metamod-P `meta_api.h`, `mutil.h`, `eiface.h`, the ReGameDLL-CS bot init and
manager files as behavior-only references, `AGENTS.md`, and
`C_CPP_REFACTOR_RULES.md`. The guard may use public engine functions and
edict fields only. It must not include or link ReGameDLL bot headers or
assume a private manager address. Preserve user files and do not add local
FocalSpan index files to the manifest.
</context>

<tasks>

### Task 1: Write the failing native-guard tests

**Type:** test
**Files:** `tests/native_bot_guard_tests.cpp`, `CMakeLists.txt`

**Action:** Add SDK-free tests for guard arming, missing CVar/setter
capability, native controls being nonzero, blocked native bot command names,
an unmanaged FakeClient, an AstraBot-owned FakeClient, and clean teardown.
Assert that any uncertainty returns a non-creatable/fail-closed decision,
while an explicitly verified clean snapshot returns an allow decision. Keep
the expected command list independent from production implementation data.

**Verify:** Build/run before adding guard production code. It must fail for
the missing guard API rather than test syntax or fixture errors.

**Acceptance criteria:** Native-ownership cases are red-tested before code.

### Task 2: Implement the pure guard decision layer

**Type:** implementation
**Files:** `include/astrabot/metamod/native_bot_guard.hpp`,
`src/adapter/metamod/native_bot_guard.cpp`, `CMakeLists.txt`

**Action:** Define a bounded guard state machine that consumes value
observations: whether required public controls exist, current
`bot_enable`/`bot_quota`, registered command names, all fake-client slots,
and AstraBot-owned slots. Return explicit `Clean`, `Suppressed`,
`Conflict`, or `Unsupported` decisions plus a stable reason code. Do not
store `edict_t*`, call engine functions, or claim that a native bot is safe
merely because a CVar was set once. Use named constants for the supported
native command set and all bounds.

**Verify:** Run the native-guard tests through red/green/refactor and all
portable tests. Confirm no SDK include is needed by the pure decision layer.

**Acceptance criteria:** The decision is deterministic, fail-closed for
missing evidence/conflicts, and distinguishes owned from unmanaged slots.

### Task 3: Wire the guard to public Metamod/engine hooks

**Type:** implementation
**Files:** `src/adapter/metamod/plugin_runtime.hpp`,
`src/adapter/metamod/plugin_runtime.cpp`,
`src/adapter/metamod/native_bot_guard.cpp`

**Action:** During map activation, obtain the public engine hook tables via
the Metamod utility boundary when available, snapshot the native bot CVars,
and set `bot_enable` and `bot_quota` to zero only after the setter and
observations are validated. Preserve the prior values for orderly teardown;
do not restore them until AstraBot ownership is inactive. Hook
`pfnAddServerCommand` and supercede the native ReGameDLL bot command names
while the guard is armed. Leave unrelated server commands untouched.

On each frame, re-check the public controls and inspect only the bounded
client edict range for `FL_FAKECLIENT`. Compare those slots to the future
AstraBot ownership registry; in this phase the registry is empty, so any
unmanaged fake client is a conflict. A missing hook table, missing CVar,
setter failure, invalid client range, or unexpected fake client must disable
managed-Bot creation and emit a diagnostic with map/round/frame context.

Do not state that CVar suppression alone proves isolation. Diagnostics must
distinguish `suppressed`, `unmanaged_fakeclient`, `unsupported_boundary`, and
`native_control_reenabled`.

**Verify:** Extend adapter tests with fake public engine functions and a
deterministic edict fixture. Run Windows/Linux x86 ABI, hook, lifecycle, and
native-guard tests. Verify the native command hook returns the expected
Metamod result and never calls an unrelated command path.

**Acceptance criteria:** The runtime never creates a managed Bot while
native ownership is unproven and does not mix native and AstraBot actors.
