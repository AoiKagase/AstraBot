<objective>
Implement actor-specific CSBot behavior state transitions and a bounded
objective-proposal boundary above WorldSnapshot and Perception.
</objective>

<tasks>

### Task 1: Write failing behavior and proposal tests

Cover initial, roam, seek, engage, retreat, dead, round-reset, and recovery
transitions; actor/map/round generation changes; unavailable observations;
objective proposal priority and expiry; and the distinction between a
proposal, an action intent, and completion feedback.

### Task 2: Define state and proposal contracts

Add bounded enums and value records for behavior state, transition reason,
objective kind, priority, proposal expiry, and actor-scoped decision context.
Require explicit Unknown/Unavailable inputs and preserve source observation
stamps. Avoid global mutable state and hidden engine truth.

### Task 3: Implement deterministic transition and selection logic

Consume an immutable WorldSnapshot and perception result, apply explicit
priority/tie-breaking rules, reject stale generations, and return bounded
proposals with recovery results. Do not emit weapon, movement, or dispatch
success from a state transition alone.

### Task 4: Verify Core-only integration

Register sources/tests, run focused and complete x86 offline suites, and
verify that behavior code includes no Metamod/HLSDK headers or Entity pointers.

</tasks>

<must_haves>

- State is actor-specific and generation-scoped.
- Unknown observation cannot produce omniscient state or completed objective.
- Every transition has a bounded, deterministic recovery path.

</must_haves>

<verification>

1. Observe behavior tests fail before implementation.
2. Run Windows/Linux x86 Core and Metamod regression suites.
3. Keep real-server state parity acceptance pending Phase 8.
