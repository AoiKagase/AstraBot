# Plan 08-07: live combat and C4 action adapter

## Objective

Connect the existing SDK-free combat/objective decisions to the public
Metamod/HLSDK input boundary so that a joined AstraBot can emit observable
attack, reload, plant, and defuse inputs. Keep navigation dispatch and each
live log gate independent.

## Comparator constraints

- ReGameDLL-CS uses `PrimaryAttack()` for a held C4 plant or combat attack and
  `UseEnvironment()` for defuse; its private implementation is comparator-only.
- YaPB translates per-frame `pev->button` state and passes it to
  `pfnRunPlayerMove`; RealBot uses bounded `UTIL_BotPressKey`/FakeClient
  command paths for attack, reload, weapon selection, and use.
- AstraBot will use only the public `edict_t`, engine function table,
  `pfnRunPlayerMove`, and GameDLL client-command boundary.

## Tasks

### 1. RED adapter contract

- Add a focused adapter test that passes Core fire/reload and objective
  proposals and asserts the exact `IN_ATTACK`, `IN_USE`, and reload command
  outputs, including the no-op path for invalid/stale proposals.
- Add an integration assertion that the runtime preserves locomotion buttons
  while adding the action button and target view angles.
- Run the focused test before production changes and record the expected RED
  failure.

### 2. Implement the action bridge

- Add a small adapter-owned action decision type and translation function.
- Build a bounded per-frame world snapshot from alive client slots and the
  visible objective entities available through the engine function table.
- Invoke `CombatController` and `RoundObjectivePlanner` with that snapshot;
  translate fire/reload and plant/defuse proposals without claiming engine
  success before `RunPlayerMove`/GameDLL dispatch returns.
- Preserve the existing movement command and combine buttons rather than
  replacing navigation input.

### 3. Runtime and diagnostics

- Reset per-slot action state on map/round/slot cleanup.
- Emit offset-scoped `combat action=...`, `objective action=...`, and dispatch
  result logs with actor slot/generation/frame.
- Keep C4 plant/defuse evidence based on fresh server log events, not adapter
  proposal logs.

### 4. Verification

- Run RED→GREEN focused adapter/runtime tests, then the existing movement,
  locomotion, and compatibility actor-command tests.
- Rebuild the current x86 source with the known fresh MSVC configuration,
  refresh FocalSpan and CRG, and inspect the final diff.
- Deploy only after the source DLL identity is captured; run the existing
  offset-scoped live verifier for movement, Bot-to-Bot damage, plant, and
  defuse independently.
- Keep Linux x86, pinned differential trace, and full multi-Bot acceptance
  pending unless their own gates pass.

## Completion conditions

- Focused adapter tests prove Core proposal → public input dispatch.
- A fresh live interval contains a nonzero Bot-to-Bot attack line; C4 plant
  and defuse remain separate pass/fail gates.
- No claim of Phase 8 completion is made while any required live gate is
  missing.
