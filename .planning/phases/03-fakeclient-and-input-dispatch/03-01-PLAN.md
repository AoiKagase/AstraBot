<objective>
Create a bounded actor registry and public-boundary FakeClient manager with
explicit reserve/join/remove/reuse states, preserving the Phase 2 native
guard and lifecycle generations.
</objective>

<context>
Read `03-CONTEXT.md`, Phase 2 plans/summaries, the approved design,
`AGENTS.md`, and `C_CPP_REFACTOR_RULES.md`. Use only public
`pfnCreateFakeClient`, `pfnIndexOfEdict`, `pfnPEntityOfEntIndex`, and GameDLL
callback table entries. Do not include ReGameDLL bot headers or copy its
CreateBot implementation. Tests must use fake function tables and never call
the real engine.
</context>

<tasks>

### Task 1: Write failing actor and manager tests

**Type:** test
**Files:** `tests/actor_registry_tests.cpp`,
`tests/fake_client_manager_tests.cpp`, `CMakeLists.txt`

**Action:** Add tests for bounded slot reservation, join completion, actor
  generation changes on release/reuse, duplicate operations, invalid slots,
  missing engine capability, null FakeClient return, and removal ordering.
  Assert that a failed create/join/remove never publishes an actor record and
  that an old `ActorId` cannot address a reused slot. Define fake public
  engine/GameDLL callbacks in test-only code.

**Verify:** Run before adding registry/manager production code. Failures must
  identify the missing API rather than a fixture or SDK problem.

**Acceptance criteria:** The actor lifecycle and failure directions are red
  tested independently of the real server.

### Task 2: Implement the SDK-free actor registry

**Type:** implementation
**Files:** `include/astrabot/runtime/actor_registry.hpp`,
`src/core/runtime/actor_registry.cpp`, `CMakeLists.txt`

**Action:** Implement a fixed-capacity `ActorRegistry` keyed by slot and
  generation. Model `Reserved`, `Joining`, `Joined`, `Removing`, and
  `Vacant` transitions with explicit results. Integrate the Phase 2
  `LifecycleToken` requirement so map/round/slot invalidation rejects stale
  actors. Bound all records and sequence values, reject wraparound, and keep
  all APIs value-oriented and deterministic.

**Verify:** Run actor registry tests through RED/GREEN/refactor and all
  portable Core tests on both x86 targets.

**Acceptance criteria:** Duplicate, stale, invalid, and actor-mismatched
  operations cannot advance registry state; reuse receives a new generation.

### Task 3: Implement the adapter FakeClient manager

**Type:** implementation
**Files:** `include/astrabot/metamod/fake_client_manager.hpp`,
`src/adapter/metamod/fake_client_manager.cpp`,
`src/adapter/metamod/plugin_runtime.hpp`,
`src/adapter/metamod/plugin_runtime.cpp`

**Action:** Add an adapter-owned manager that checks the Phase 2 managed-Bot
  gate, reserves an actor, calls public `pfnCreateFakeClient`, resolves and
  validates its slot with `pfnIndexOfEdict`, and invokes the public GameDLL
  `pfnClientPutInServer` callback in the documented order. Publish ownership
  only after every step succeeds. Removal must invalidate the actor before
  invoking public disconnect/kick cleanup and tolerate repeated teardown.
  Route `ClientPutInServer`/`ClientDisconnect` hooks through the manager so
  external and native FakeClients never become managed accidentally.

**Verify:** Run fake manager tests with null/failing callbacks, slot reuse,
  two actors, and post-detach callbacks. Build the Metamod adapter on
  Windows/Linux x86.

**Acceptance criteria:** The manager never stores an unvalidated edict as a
  managed actor and does not create actors while native ownership is
  unproven.

### Task 4: Apply source rules and inspect boundary

**Type:** refactor
**Files:** all C/C++ files changed by this plan

**Action:** Keep SDK types at the adapter boundary, use real tabs/LF/BOM-free
  UTF-8, named limits, explicit null/result handling, and no broad unrelated
  refactor.

**Verify:** Run focused tests, `git diff --check`, and source-format checks.

**Acceptance criteria:** Registry and manager responsibilities are isolated
  and reviewable.
