<objective>
Define value-based Bot input commands and bounded receipts, then dispatch
current actor commands through public `pfnRunPlayerMove` on the main thread.
</objective>

<context>
Read `03-CONTEXT.md`, `03-01-SUMMARY.md`, Phase 2 lifecycle contracts,
`C_CPP_REFACTOR_RULES.md`, and the pinned `eiface.h` RunPlayerMove signature.
Core command values must not contain `edict_t`, SDK vectors, or function
tables. Dispatch must be the only code that calls `pfnRunPlayerMove`.
</context>

<tasks>

### Task 1: Write failing command/receipt tests

**Type:** test
**Files:** `tests/command_queue_tests.cpp`,
`tests/input_dispatcher_tests.cpp`, `CMakeLists.txt`

**Action:** Test command sequence ordering, bounded queue overflow,
  actor/generation mismatch, stale map/round rejection, invalid movement
  values, duplicate receipt, rejected dispatch, and successful dispatch
  acknowledgment. Verify two actors cannot consume each other's commands.

**Verify:** Run before adding command/queue/dispatcher production code and
  capture the intended missing-API failure.

**Acceptance criteria:** Every rejection direction is independently red
  tested with real value objects.

### Task 2: Implement Core command and queue contracts

**Type:** implementation
**Files:** `include/astrabot/runtime/bot_command.hpp`,
`src/core/runtime/bot_command.cpp`,
`include/astrabot/runtime/command_queue.hpp`,
`src/core/runtime/command_queue.cpp`, `CMakeLists.txt`

**Action:** Define SDK-free view-angle/movement/button values, a monotonic
  sequence, `ActorId`/`LifecycleToken` stamp, and explicit command/receipt
  result enums. Implement a fixed-capacity per-runtime queue with deterministic
  full/empty behavior, no unbounded allocation, no sequence wrap acceptance,
  and no state advancement for rejected commands.

**Verify:** Run queue tests through RED/GREEN/refactor and all Core tests.

**Acceptance criteria:** Queue acceptance is actor-specific, generation
  validated, bounded, and deterministic.

### Task 3: Implement main-thread input dispatcher

**Type:** implementation
**Files:** `include/astrabot/metamod/input_dispatcher.hpp`,
`src/adapter/metamod/input_dispatcher.cpp`,
`src/adapter/metamod/plugin_runtime.hpp`,
`src/adapter/metamod/plugin_runtime.cpp`

**Action:** Drain only current actor commands at the frame dispatch point,
  resolve the owned edict through the registry, validate queue receipt and
  current lifecycle token, then call public `pfnRunPlayerMove` with converted
  scalar values. Return an explicit receipt containing actor, sequence,
  dispatch frame, and result. Reject null/stale/missing engine capability or
  non-finite/out-of-range values before the engine call. Never dispatch from a
  worker thread or after detach.

**Verify:** Use fake `pfnRunPlayerMove` callbacks to assert exact arguments,
  call count, ordering, actor isolation, rejection, and queue overflow. Build
  and run Windows/Linux x86 adapter tests.

**Acceptance criteria:** A successful queue/dispatch receipt is the only
  evidence of an input call; rejected commands cannot move actor state.

### Task 4: Refactor and verify ABI boundary

**Type:** refactor
**Files:** all C/C++ files changed by this plan

**Action:** Apply `C_CPP_REFACTOR_RULES.md`, preserve public SDK ABI, keep
  dispatch ownership in one adapter unit, and remove duplicated conversion
  logic.

**Verify:** Run focused/full x86 tests, source-format checks, and
  `git diff --check`.

**Acceptance criteria:** Core remains SDK-free and `RunPlayerMove` has one
  auditable call path.

</tasks>
