<objective>
Establish a reproducible C++14 CMake project that rejects x64 configurations, builds a portable SDK-free Core target, and exposes a tested x86 build identity for later plugin plans.
</objective>

<context>
Read `.planning/phases/01-foundation-and-abi/01-CONTEXT.md` and `docs/superpowers/specs/2026-09-15-astrabot-csbot-clone-design.md`. Preserve `.focalspan/`, `.focalspan.json`, `C_CPP_REFACTOR_RULES.md`, and all unrelated files. Use C++14 to match the pinned ReGameDLL build, keep Core free of SDK includes, and configure Windows with VS18 x86 NMake and Linux with `-m32`.
</context>

<tasks>

### Task 1: Define the project and build options

**Type:** implementation
**Files:** `CMakeLists.txt`, `cmake/AstraBotBuild.cmake`, `.gitignore`
**Action:** Create the root CMake project with options `ASTRABOT_BUILD_METAMOD`, `ASTRABOT_BUILD_TESTS`, `ASTRABOT_WARNINGS_AS_ERRORS`, and `ASTRABOT_METAMOD_SDK_ROOT`. Set C++14 as required, enable position-independent code for future plugin targets, add `src/core` and `tests` targets only when their options are enabled, and include a configure-time pointer-size check that fails unless `sizeof(void*)` is 4. Put compiler/platform warning helpers in `cmake/AstraBotBuild.cmake`; apply warnings to AstraBot code without treating external SDK headers as project sources. Add `build/`, `build-*`, `cmake-build-*`, and `compile_commands.json` to `.gitignore` while preserving the existing `.focalspan/` rule.
**Verify:** Configure the project with `ASTRABOT_BUILD_METAMOD=OFF` and `ASTRABOT_BUILD_TESTS=ON`; the configure summary must report a 32-bit target and C++14. Configure once with an x64 compiler and confirm it fails with the project x86 diagnostic.
**Acceptance criteria:** The project has no dependency on ReGameDLL source files, no default x64 success path, and a portable target can be selected without the Metamod SDK.

### Task 2: Add the Core build identity contract

**Type:** implementation
**Files:** `include/astrabot/build_identity.hpp`, `src/core/build_identity.cpp`
**Action:** Define a small SDK-free namespace `astrabot::build` with value-returning functions for pointer width, C++ standard level, target architecture name, and project version. Implement the values from compile-time checks and CMake definitions. Use `static_assert(sizeof(void*) == 4)` in the project target and do not expose compiler-specific or SDK types.
**Verify:** Build the Core target with warnings-as-errors on Windows x86 Debug and Linux x86 Debug; the compiler must emit no warnings for the new files.
**Acceptance criteria:** Later plans can include one stable header to report build identity, and the header compiles without any Metamod/HLSDK include path.

### Task 3: Add deterministic build identity tests

**Type:** test
**Files:** `tests/build_identity_tests.cpp`, `CMakeLists.txt`
**Action:** Add a small executable/CTest case that asserts pointer width is 32, the C++ standard value is 14, architecture is the expected x86 value, and the version string is non-empty. Register the test only under `ASTRABOT_BUILD_TESTS` and make its output identify the target architecture.
**Verify:** Run `ctest --test-dir build-portable-x86-test -R '^astrabot_build_identity$' --output-on-failure`; expect one passing test. Discover the registered name first with `ctest --test-dir build-portable-x86-test -N`.
**Acceptance criteria:** The same test source is usable on Windows x86 and Linux x86 and fails if a future configuration silently changes to x64 or an unsupported C++ standard.

### Task 4: Commit the foundation slice

**Type:** commit
**Files:** `CMakeLists.txt`, `.gitignore`, `cmake/AstraBotBuild.cmake`, `include/astrabot/build_identity.hpp`, `src/core/build_identity.cpp`, `tests/build_identity_tests.cpp`
**Action:** Inspect the explicit diff, confirm no SDK or reference-repository files are staged, and create an atomic commit named `build: establish x86 CMake foundation`.
**Verify:** Run `git diff --cached --check` and `git status --short` after staging the six listed paths; the commit must contain only those intended paths.
**Acceptance criteria:** The foundation commit is reproducible and leaves unrelated untracked files untouched.

</tasks>
