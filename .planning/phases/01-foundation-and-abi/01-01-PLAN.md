<objective>
Establish a reproducible C++14 CMake project that rejects x64 configurations, builds a portable SDK-free Core target, and exposes a tested x86 build identity for later plugin plans.
</objective>

<context>
Read `.planning/phases/01-foundation-and-abi/01-CONTEXT.md` and `docs/superpowers/specs/2026-09-15-astrabot-csbot-clone-design.md`. Use C++14 to match the pinned ReGameDLL build, keep Core free of SDK includes, and configure Windows with VS18 x86 NMake and Linux with `-m32`.
</context>

<tasks>

### Task 1: Define the project and build options

**Type:** implementation
**Files:** `CMakeLists.txt`, `cmake/AstraBotBuild.cmake`, `.gitignore`
**Action:** Create the root CMake project with options `ASTRABOT_BUILD_METAMOD`, `ASTRABOT_BUILD_TESTS`, `ASTRABOT_WARNINGS_AS_ERRORS`, and `ASTRABOT_METAMOD_SDK_ROOT`. Set C++14 as required, enable position-independent code for future plugin targets, add the test executable from its test source without a production Core source yet, and include a configure-time pointer-size check that fails unless `sizeof(void*)` is 4. Put compiler/platform warning helpers in `cmake/AstraBotBuild.cmake`; apply warnings to AstraBot code without treating external SDK headers as project sources. Add `build/`, `build-*`, `cmake-build-*`, and `compile_commands.json` to `.gitignore` while preserving the existing `.focalspan/` rule.
**Verify:** Configure the project with `ASTRABOT_BUILD_METAMOD=OFF` and `ASTRABOT_BUILD_TESTS=ON`; the configure summary must report a 32-bit target and C++14. Configure once with an x64 compiler and confirm it fails with the project x86 diagnostic.
**Acceptance criteria:** The project has no dependency on ReGameDLL source files, no default x64 success path, and a portable target can be selected without the Metamod SDK.

### Task 3: Implement the Core build identity contract

**Type:** implementation
**Files:** `include/astrabot/build_identity.hpp`, `src/core/build_identity.cpp`
**Action:** Define a small SDK-free namespace `astrabot::build` with value-returning functions for pointer width, C++ standard level, target architecture name, and project version. Add `astrabot_core` from `src/core/build_identity.cpp` and link the existing `astrabot_build_identity` test to it. Implement the values from compile-time checks and CMake definitions. Use `static_assert(sizeof(void*) == 4)` in the project target and do not expose compiler-specific or SDK types.
**Verify:** Rebuild the Core target with warnings-as-errors on Windows x86 Debug and Linux x86 Debug, then run `ctest --test-dir build-portable-x86-test -R '^astrabot_build_identity$' --output-on-failure`; expect one passing test and no warnings for the new files.
**Acceptance criteria:** Later plans can include one stable header to report build identity, and the header compiles without any Metamod/HLSDK include path.
