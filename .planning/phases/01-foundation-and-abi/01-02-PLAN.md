<objective>
Define the public Metamod-P ABI boundary and build a minimal x86 plugin artifact with the required C exports, without installing hooks or implementing Bot behavior.
</objective>

<context>
Read `.planning/phases/01-foundation-and-abi/01-CONTEXT.md`, Plan 01-01, and the pinned Metamod-P headers under `H:/sourcecode/003.Game/amxmodx/metamod-p`. Use those headers by include path; do not copy them. The export contract must remain C ABI and must not expose AstraBot C++ classes. The actual lifecycle hooks and native Bot guard belong to Phase 2.
</context>

<tasks>

### Task 1: Define the ABI include boundary

**Type:** implementation
**Files:** `CMakeLists.txt`, `cmake/AstraBotBuild.cmake`, `include/astrabot/metamod/abi_contract.hpp`
**Action:** Add the cache path `ASTRABOT_METAMOD_SDK_ROOT` and, when `ASTRABOT_BUILD_METAMOD=ON`, add only the required external include directories for `metamod-p/metamod` and `metamod-p/hlsdk` subtrees. Mark those include directories as system/external where the compiler supports it. Define a project-owned header that documents the six required C exports and the supported interface constants without re-declaring SDK structs. Keep all ABI declarations sourced from the pinned SDK headers.
**Verify:** Configure with `ASTRABOT_BUILD_METAMOD=ON` and an explicit SDK root at `H:/sourcecode/003.Game/amxmodx/metamod-p`; a missing SDK root must fail with a clear configure error, while the valid root must not copy files into the project.
**Acceptance criteria:** The target has a single explicit external SDK root, no relative include traversal into ReGameDLL, and no private GameDLL include.

### Task 2: Implement safe minimal C exports

**Type:** implementation
**Files:** `src/adapter/metamod/plugin_exports.cpp`, `CMakeLists.txt`
**Action:** Define the required `extern "C"` exports using the Metamod-P/HLSDK declarations: `Meta_Query`, `Meta_Attach`, `Meta_Detach`, `GetEntityAPI2`, `GetEngineFunctions`, and `GiveFnptrsToDll`. Provide valid plugin metadata and interface-version checks. Return safe failure or an empty function table for unimplemented behavior; do not register gameplay hooks, create FakeClients, call private symbols, or throw exceptions. Build the source as `astrabot_mm` with shared-library export visibility and x86-only settings.
**Verify:** Build `astrabot_mm` in Windows x86 Debug and Linux x86 Debug with the pinned SDK root. Inspect symbols with `dumpbin /exports` on Windows and `readelf -Ws` on Linux; each of the six names must be present exactly once and undecorated.
**Acceptance criteria:** The artifact is loadable at the ABI level, exports exactly the approved names, and contains no CSBot behavior that belongs to later phases.

### Task 3: Add ABI compile and export contract tests

**Type:** test
**Files:** `tests/metamod_abi_tests.cpp`, `CMakeLists.txt`
**Action:** Add a host-side test that includes `abi_contract.hpp`, assigns each export to the SDK-declared function-pointer shape, checks the expected Metamod interface version constants, and verifies the plugin metadata name/version are non-empty. Keep this test independent of a running server. Register it as `astrabot_metamod_abi` under the Metamod test option.
**Verify:** Run `ctest --test-dir build-metamod-x86-test -R '^astrabot_metamod_abi$' --output-on-failure`; expect one passing test. Run the export inspection separately because a host test cannot prove the final shared-library symbol table.
**Acceptance criteria:** ABI drift fails at compile/test time, and export identity is checked as a separate artifact property.

### Task 4: Commit the ABI slice

**Type:** commit
**Files:** `CMakeLists.txt`, `cmake/AstraBotBuild.cmake`, `include/astrabot/metamod/abi_contract.hpp`, `src/adapter/metamod/plugin_exports.cpp`, `tests/metamod_abi_tests.cpp`
**Action:** Inspect the diff and staged paths, confirm no SDK/reference files were copied or staged, and create an atomic commit named `feat: add Metamod ABI plugin boundary`.
**Verify:** Run `git diff --cached --check`, inspect export names from the built artifact, and record the SDK commit used by the build.
**Acceptance criteria:** The commit builds the minimal plugin for both x86 targets and leaves lifecycle behavior for Phase 2.

</tasks>
