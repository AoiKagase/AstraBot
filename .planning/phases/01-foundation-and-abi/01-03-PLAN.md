<objective>
Make Phase 1 source provenance, reference pins, x86 architecture, and required export checks repeatable without copying reference code or relying on graph indexes as current proof.
</objective>

<context>
Read `.planning/phases/01-foundation-and-abi/01-CONTEXT.md`, Plans 01-01 and 01-02, `AGENTS.md`, and the approved design. The reference repositories are external read-only inputs. The manifest must cover every AstraBot implementation/test/tool file created by Phase 1 and record the exact ReGameDLL-CS and Metamod-P commits. The verification scripts are tooling only; they must not become runtime dependencies.
</context>

<tasks>

### Task 1: Record source and reference provenance

**Type:** documentation
**Files:** `docs/source-manifest.json`
**Action:** Create a versioned JSON manifest with schema version, project name, release-license status, reference repository paths/commits/roles, and an explicit list of every Phase 1 file under `src`, `include`, `tests`, and `tools`. Mark AstraBot files as independently authored and reference repositories as behavior/SDK-only. Record that no ReGameDLL-CS Bot source or private implementation is included.
**Verify:** Parse the manifest with Python's standard `json` module and confirm the two reference SHAs equal `b0889847fe6d03898be88acc9e366660efb40ab5` and `7ec9b014f8c0a947a724644aebe34eb33706e44b`.
**Acceptance criteria:** A reviewer can identify the origin and allowed use of every Phase 1 source file without inspecting Git history.

### Task 2: Implement the manifest checker

**Type:** tooling
**Files:** `tools/check_source_manifest.py`
**Action:** Implement a standard-library-only checker with explicit `--root` and `--manifest` arguments. Validate schema/version, reference SHA fields, path existence, duplicate paths, allowed origin values, and exact coverage of all `.c`, `.cc`, `.cpp`, `.h`, and `.hpp` files under `src`, `include`, `tests`, and `tools`. Exclude build directories and `.focalspan` by explicit path rules. Exit non-zero for missing, extra, duplicated, or unapproved entries and print the failing path/reason.
**Verify:** Run `python tools/check_source_manifest.py --root . --manifest docs/source-manifest.json`; expect a passing summary. Copy the manifest to a temporary file, remove one listed path, run the checker, and confirm it fails for the missing entry without changing the repository.
**Acceptance criteria:** Provenance drift is detected deterministically on Windows and Linux using only the Python standard library.

### Task 3: Implement the x86/export verifier

**Type:** tooling
**Files:** `tools/verify_x86_artifact.py`
**Action:** Implement a platform-aware checker with `--path`, `--format pe|elf`, and repeated `--export` arguments. For PE, invoke the active `dumpbin /headers` and `/exports` tools and require a 32-bit image plus an export set containing exactly the six requested names. For ELF, invoke `file` and `readelf -Ws` and require ELF 32-bit Intel 80386 plus the same exact export set. Reject missing tools, 64-bit artifacts, extra exported project symbols, duplicate required exports, and decorated-only Windows names. Keep expected exports supplied by arguments so the checker can be reused for later plugin versions.
**Verify:** Run the checker against the Phase 1 Windows DLL with the six required names and against the Linux `.so` with the same names. Pass a known 64-bit or wrong-format file in a temporary path and confirm a non-zero result with a specific diagnostic.
**Acceptance criteria:** Architecture and export evidence is generated from the actual artifact rather than inferred from CMake configuration, and any extra or decorated-only export fails the check.

### Task 4: Run the Phase 1 verification harness

**Type:** verification
**Files:** `docs/source-manifest.json`, `tools/check_source_manifest.py`, `tools/verify_x86_artifact.py`
**Action:** Run the manifest checker, portable x86 build/test checks, Metamod x86 ABI test, and artifact verifier for both platforms. Record commands, toolchain identity, SDK SHA, artifact path, and result in the Phase 1 execution evidence used by GSD; do not add generated binaries to Git.
**Verify:** Confirm all applicable checks pass, `git diff --check` is clean, `git status --short` shows only intentionally untracked local files, and the code-review graph/FocalSpan status is refreshed after the plan is executed.
**Acceptance criteria:** Phase 1 can be audited from source manifest plus actual build/test/export outputs, with offline and live-server claims kept separate.

### Task 5: Commit the provenance slice

**Type:** commit
**Files:** `docs/source-manifest.json`, `tools/check_source_manifest.py`, `tools/verify_x86_artifact.py`
**Action:** Stage only the three listed files and create an atomic commit named `chore: add Phase 1 provenance checks`.
**Verify:** Run `git diff --cached --check`, inspect the staged path list, and confirm `.focalspan/`, `.focalspan.json`, and unrelated files are not staged.
**Acceptance criteria:** The Phase 1 evidence tooling is versioned and the working tree remains free of generated artifacts.
