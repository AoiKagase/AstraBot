<objective>
Parse bounded Bot profile input into a clean-room format-neutral catalog and
provide deterministic name/difficulty/team selection for the compatibility
surface.
</objective>

<context>
Read `04-CONTEXT.md`, `04-01-SUMMARY.md`, the pinned ReGameDLL-CS profile
input/reference behavior, `C_CPP_REFACTOR_RULES.md`, and the project source
manifest rules. Do not copy `BotProfileManager`, profile classes, or parser
code. Profile files are read-only inputs and must not be modified.
</context>

<tasks>

### Task 1: Write failing profile tests

**Type:** test
**Files:** `tests/profile_catalog_tests.cpp`,
`tests/profile_loader_tests.cpp`, `CMakeLists.txt`

**Action:** Test valid minimal profiles, quoted names, team/difficulty fields,
  duplicate names, unknown profiles, malformed/oversized input, bounded
  record counts, deterministic random-selection injection, and read-only file
  loading.

**Verify:** Run before catalog/loader implementation and capture the expected
  missing-API failure.

**Acceptance criteria:** Profile behavior is specified by real value tests,
  not copied implementation structure.

### Task 2: Implement Core profile catalog

**Type:** implementation
**Files:** `include/astrabot/compat/profile_catalog.hpp`,
`src/core/compat/profile_catalog.cpp`, `CMakeLists.txt`

**Action:** Implement fixed-capacity profile records with explicit name,
  team, difficulty, aggression/skill values, and selection result. Reject
  duplicate/invalid records and unsafe allocations. Keep selection
  deterministic under an injected index/RandomSource value and return
  explicit fallback/unknown results.

**Verify:** Run catalog tests through RED/GREEN/refactor and all prior tests.

**Acceptance criteria:** Core profile selection has no SDK/file dependency.

### Task 3: Implement adapter read-only profile loader

**Type:** implementation
**Files:** `include/astrabot/metamod/profile_loader.hpp`,
`src/adapter/metamod/profile_loader.cpp`,
`src/adapter/metamod/compat_surface.cpp`

**Action:** Add a bounded loader using the existing adapter file boundary,
  parse only the supported compatibility fields, publish a complete catalog
  transactionally, and report missing/malformed/oversized data explicitly.
  Integrate profile lookup into `bot_add` argument resolution without creating
  an actor in this plan.

**Verify:** Use temporary read-only fixtures; assert source bytes remain
  unchanged and invalid input never publishes a partial catalog.

**Acceptance criteria:** COMP-02 profile input remains usable and isolated
  from ReGameDLL implementation.

### Task 4: Update provenance and source rules

**Type:** documentation/verification
**Files:** `docs/source-manifest.json` and changed C/C++ files

**Action:** Register all new files, run focused/full x86 tests, manifest,
  FocalSpan, CRG, and `git diff --check`.

**Acceptance criteria:** Profile compatibility has current offline evidence.

</tasks>
