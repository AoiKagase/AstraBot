<objective>
Wire the compatibility surface to Phase 3 actor operations so existing
server commands can enable/disable, add/remove, choose team/difficulty, and
set quota without bypassing generations or native guard policy.
</objective>

<context>
Read `04-CONTEXT.md`, `04-01-SUMMARY.md`, `04-02-SUMMARY.md`, Phase 2/3
contracts, ReGameDLL-CS command behavior references, `AGENTS.md`, and
`C_CPP_REFACTOR_RULES.md`. Do not change Nav or behavior AI. Every command
must route through PluginRuntime actor/receipt APIs; no direct FakeClient or
private GameDLL calls may be introduced.
</context>

<tasks>

### Task 1: Write failing configuration/actor-command tests

**Type:** test
**Files:** `tests/bot_configuration_tests.cpp`,
`tests/compat_actor_command_tests.cpp`, `CMakeLists.txt`

**Action:** Test desired enable/disable/stop/difficulty/team/quota state,
  `bot_add`, `bot_add_t`, `bot_add_ct`, `bot_kick`, and `bot_kill` argument
  behavior, quota accounting, team/full-slot rejection, stale handle
  rejection, native guard denial, and repeated remove. Assert invalid input
  leaves configuration and actor registry unchanged.

**Verify:** Run before configuration/command wiring and capture missing API
  failures.

**Acceptance criteria:** COMP-03 operational behavior is red-tested through
  public value/adapter boundaries.

### Task 2: Implement Core bot configuration

**Type:** implementation
**Files:** `include/astrabot/compat/bot_configuration.hpp`,
`src/core/compat/bot_configuration.cpp`, `CMakeLists.txt`

**Action:** Implement bounded desired-state configuration, team-selection,
  quota accounting, and explicit command action requests. Keep native
  suppression separate from operator desired state; rejected action requests
  must not mutate quota or actor identity.

**Verify:** Run configuration tests through RED/GREEN/refactor and prior x86
  tests.

**Acceptance criteria:** Desired state is deterministic and side-effect safe.

### Task 3: Wire commands to Phase 3 actors

**Type:** implementation
**Files:** `src/adapter/metamod/compat_surface.cpp`,
`src/adapter/metamod/plugin_runtime.cpp`

**Action:** Route parsed add/remove/team/difficulty actions to the
  generation-safe FakeClient and receipt APIs, update managed ownership slots
  only after successful operations, and report command results through bounded
  diagnostics. Preserve native guard behavior and exact public command names.
  Never claim gameplay success from actor creation alone.

**Verify:** Fake-host tests cover two actors, quota changes, repeated commands,
  stale handles, native conflict, and CVar/command result traces on
  Windows/Linux x86.

**Acceptance criteria:** COMP-03 is wired without bypassing Phase 2/3 safety.

### Task 4: Finalize provenance and Phase 4 verification

**Type:** verification/documentation
**Files:** `docs/source-manifest.json`, Phase 4 summaries/verification,
  changed source/test files

**Action:** Run full x86 CTest, manifest, PE/ELF six-export checks, source
  format, FocalSpan update/query, CRG current-head impact, and final staged
  diff review. Keep live configuration migration and gameplay acceptance
  separate.

**Acceptance criteria:** COMP-01/02/03 and TEST-02 have auditable offline
  evidence.

### Task 5: Commit the Phase 4 slice

**Type:** commit
**Files:** all intended Phase 4 source/tests/docs

**Action:** Explicitly stage only Phase 4 paths, run `git diff --cached --check`,
  and create one atomic commit after verification.

**Acceptance criteria:** Phase 4 compatibility surface is complete without
  claiming full CSBot parity.
