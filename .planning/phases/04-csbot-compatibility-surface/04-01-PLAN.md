<objective>
Define a format-neutral CSBot compatibility registry and desired-state CVar
model, then expose the safe public command/CVar hook boundary without adding
actor behavior yet.
</objective>

<context>
Read `04-CONTEXT.md`, Phase 3 summaries, the approved design,
`C_CPP_REFACTOR_RULES.md`, ReGameDLL-CS bot init/manager references, and
Metamod-P `eiface.h`/`meta_api.h`. Native guard ownership must remain
explicit: allow only AstraBot callbacks registered through the new surface;
unknown or native ownership is blocked.
</context>

<tasks>

### Task 1: Write failing command/CVar tests

**Type:** test
**Files:** `tests/compat_command_registry_tests.cpp`,
`tests/compat_cvar_state_tests.cpp`, `CMakeLists.txt`

**Action:** Test exact required command names, case handling, unknown/duplicate
  rejection, argument count/type/team validation, handled status, desired
  CVar updates for enable/stop/difficulty/quota/team, invalid-state no-op,
  and native-vs-AstraBot registration ownership.

**Verify:** Run before production registry/model code and record missing-API
  failures.

**Acceptance criteria:** The compatibility contract is red-tested without
  importing ReGameDLL classes or server state.

### Task 2: Implement Core command/CVar contracts

**Type:** implementation
**Files:** `include/astrabot/compat/command_registry.hpp`,
`src/core/compat/command_registry.cpp`,
`include/astrabot/compat/cvar_state.hpp`,
`src/core/compat/cvar_state.cpp`, `CMakeLists.txt`

**Action:** Implement bounded exact-name command specs and a desired-state
  CVar model for the required CSBot surface. Use explicit parse/result enums,
  named limits, no global mutable command table, and no SDK types. Preserve
  user intent separately from native suppression state so Phase 2's guard
  cannot silently reinterpret an AstraBot CVar.

**Verify:** Run Core tests through RED/GREEN/refactor and all prior x86 Core
  tests.

**Acceptance criteria:** Invalid commands/CVars are side-effect free and
  desired states are deterministic.

### Task 3: Add AstraBot-owned Metamod compatibility surface

**Type:** implementation
**Files:** `include/astrabot/metamod/compat_surface.hpp`,
`src/adapter/metamod/compat_surface.cpp`,
`src/adapter/metamod/native_bot_guard.cpp`,
`src/adapter/metamod/plugin_runtime.cpp`

**Action:** Register AstraBot-owned command callbacks through the public
  `pfnAddServerCommand` boundary with an ownership marker recognized by the
  native guard. Route command input to Core parsing and CVar desired state;
  leave actor creation/team actions for Plans 04-03 and Phase 3 APIs. Expose
  diagnostics for handled/rejected/blocked ownership.

**Verify:** Fake engine tests prove AstraBot callback registration is allowed,
  native callback registration is superceded, and unrelated registrations
  remain untouched. Build Windows/Linux x86.

**Acceptance criteria:** COMP-01 is wired without re-enabling native CSBot.

### Task 4: Refactor and check ABI/source rules

**Type:** refactor
**Files:** all C/C++ files changed by this plan

**Action:** Apply `C_CPP_REFACTOR_RULES.md`, isolate compatibility policy from
  actor behavior, and preserve the existing six exports.

**Verify:** Run CTest, format checks, manifest/FocalSpan/CRG checks, and
  `git diff --check`.

**Acceptance criteria:** Command/CVar contracts are testable and ownership is
  auditable.

</tasks>
