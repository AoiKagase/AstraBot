<objective>
Add bounded Jump and Drop movement envelopes with launch/landing feedback,
damage-risk limits, and explicit failure recovery.
</objective>

<context>
Read 06-CONTEXT.md, 06-01/06-02 contracts, and the legacy Nav geometry
fields. Keep jump/drop calculations conservative: unknown or non-finite
physics observations are rejected, not treated as successful traversal.
</context>

<tasks>

### Task 1: Write failing jump/drop envelope tests

Test valid launch and landing height ranges, horizontal reach, landing area
identity, drop damage-risk rejection, missing landing feedback, timeout, and
stale snapshot handling. Assert that a produced launch intent is not a
movement-success receipt.

### Task 2: Define jump/drop envelopes and feedback

Add bounded value records for launch point, landing point, maximum rise/drop,
horizontal reach, and damage-risk policy. Expose explicit result enums for
Ready, Emitted, Landed, Unsafe, TimedOut, Invalidated, and
InvalidObservation without engine types.

### Task 3: Implement conservative jump/drop state progression

Validate source/destination areas and finite observations, emit one bounded
intent per state transition, and require a later landing observation before
returning Landed. Reset or terminate on timeout, actor/map revision change,
or unsafe drop risk.

### Task 4: Verify isolated integration

Register the files, run focused and complete x86 test suites, inspect Core
include boundaries, and refresh FocalSpan/CRG evidence at the current HEAD.

</tasks>

<must_haves>
- Jump/Drop never infer success from route topology alone.
- Unsafe or unknown landings fail closed with bounded diagnostics.
- Stale generations and timeouts cannot continue the prior traversal.
</must_haves>
