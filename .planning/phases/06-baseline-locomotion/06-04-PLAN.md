<objective>
Model Ladder, Door, and NarrowPassage traversal intents with explicit
clearance, availability, and feedback states while preserving directed Nav
semantics.
</objective>

<context>
Read 06-CONTEXT.md and all prior Phase 6 contracts. These traversals must
remain capability-driven: absent adapter feedback, dynamic door state, or
ladder contact is unknown and cannot be converted into success.
</context>

<tasks>

### Task 1: Write failing special-traversal tests

Cover ladder entry/exit identity, door open/closed/unknown states, narrow
passage clearance and crouch requirement, one-way links, actor-specific
timeout/recovery, and stale route rejection. Assert that unknown dynamic
state is recoverable failure rather than an implicit open/usable state.

### Task 2: Define traversal capability and feedback contracts

Add SDK-free records for contact points, required clearance, posture, dynamic
availability, and traversal feedback. Bound every timeout and progress sample;
do not store pointers or hidden engine state.

### Task 3: Implement deterministic state machines

Implement enter, maintain, exit, complete, recover, and invalidate transitions
for Ladder/Door/NarrowPassage. Consume only supplied observations and return
one explicit intent per tick. Preserve the source direction and corridor
stamp throughout the state machine.

### Task 4: Verify no regression in ordinary locomotion

Run focused special-traversal, all portable x86, Metamod, manifest, source
format, and SDK-boundary checks. Refresh FocalSpan and CRG before preparing
the Phase 6 completion plan.

</tasks>

<must_haves>
- Dynamic door and ladder state is never fabricated.
- Narrow passages honor clearance and posture constraints.
- Recovery and invalidation remain actor/map/revision scoped.
</must_haves>

<verification>
1. Observe tests fail before implementation.
2. Run complete offline verification on Windows/Linux x86.
3. Record real-server special traversal as unverified until Phase 8.
</verification>
