<objective>
Add the first SDK-free locomotion slice: deterministic spatial lookup,
directed-link enumeration, bounded corridor search, and a snapshot-bound path
follower that only reports navigation progress.
</objective>

<context>
Read 06-CONTEXT.md, the Nav model/snapshot contracts, the Phase 5 reader
validation tests, and C_CPP_REFACTOR_RULES.md. Preserve the existing vector
and naming conventions. Do not add SDK includes, Nav write paths, or runtime
movement claims.
</context>

<interfaces>
NavQuery consumes a nav::NavSnapshot and produces NavAreaMatch,
NavDirectedLink, and NavCorridor values. NavPathFollower consumes a valid
corridor plus snapshots and returns NavFollowerResult with the next area and
target point. All public methods return explicit enum results and accept output
pointers that may be null only where the result says so.
</interfaces>

<tasks>

### Task 1: Write the failing query and follower tests

Add tests/nav_query_tests.cpp with fixtures containing overlapping areas,
one-way connections, a directed route, a disconnected area, and two snapshot
generations. Assert XY/floor containment tie-breaking, nearest-area distance,
preserved outgoing direction, successful and reverse-failing corridor search,
bounded search rejection, target progression, completion, and stale snapshot
rejection. Build the test target in CMake and run it before adding the new
production files so the intended missing-contract failure is observed.

### Task 2: Implement deterministic spatial queries

Create include/astrabot/nav/nav_query.hpp and
src/core/nav/nav_query.cpp. Define bounded NavQueryLimits, NavAreaMatch,
NavDirectedLink, NavCorridor, and NavQueryResult values. Implement finite
position validation, XY rectangle distance, floor tolerance, stable area
tie-breaking, and findContaining/findNearest without caching mutable pointers
into a snapshot.

### Task 3: Implement directed links and corridor search

Enumerate only the source area's stored connection vectors, preserving their
direction index and order-independent deterministic sorting by destination and
direction. Use a bounded breadth-first search over AreaIds for buildCorridor;
reject missing endpoints, invalid limits, queue exhaustion, and absent reverse
edges with explicit results. Reconstruct the route only after the goal is
reached and stamp it with snapshot revision/map generation.

### Task 4: Implement the snapshot-bound path follower

Add a small stateful follower that validates the corridor stamp, selects the
center of the current area as a target, advances when the supplied position is
within a finite XY tolerance and floor tolerance, and returns Reached only when
the final area has been reached. Invalid positions, invalid corridors, and
changed snapshots return explicit non-success results.

### Task 5: Verify and record the slice

Run the focused Core test, all portable x86 tests, source-format/SDK-boundary
checks, and the existing Metamod tests. Refresh FocalSpan with
focalspan update --root .; if the MCP remains unavailable, retain the CLI
evidence and report the transport limitation. Refresh CRG at the current HEAD,
inspect the impact on Nav and runtime consumers, register the new sources, and
stage only the Phase 6 slice after git diff --cached --check.

</tasks>
