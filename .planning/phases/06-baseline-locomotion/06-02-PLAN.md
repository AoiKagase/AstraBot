<objective>
Translate a valid corridor target into bounded Walk, Crouch, and Step input
intent values while validating posture clearance and step-up geometry.
</objective>

<context>
Read 06-CONTEXT.md, completed 06-01 interfaces, the BotCommand/input
contracts, and the reference behavior notes without copying ReGameDLL-CS
classes. This plan produces Core intent and feedback values; the GoldSrc
adapter remains responsible for actual RunPlayerMove calls.
</context>

<tasks>

### Task 1: Add failing posture and step-envelope tests

Cover standing versus crouching clearance, valid and excessive step heights,
horizontal corridor targets, posture changes, rejected non-finite physics
observations, and the distinction between intent emitted and movement
confirmed. Verify that a narrow route selects crouch only when the area data
allows it and that an unsupported step returns a recoverable result.

### Task 2: Define immutable locomotion intent and feedback values

Add SDK-free posture, movement-envelope, intent, and feedback enums/records.
Keep units explicit in names, bound speed/step/clearance values, and require
the caller to supply current position and floor observations. Do not place
edict_t or engine callbacks in these headers.

### Task 3: Implement Walk/Crouch/Step selection and recovery

Use the 06-01 follower target and the area extents to produce bounded forward
and side intent. Validate the current area, destination area, posture
clearance, and step height before emitting intent. Add deterministic stuck
progress counters and explicit NeedsRecovery/Invalidated results.

### Task 4: Integrate only at the Core test boundary

Compile the new tests against astrabot_core, keep runtime dispatch unchanged,
and update the source manifest. Run focused, portable x86, and existing
Metamod tests plus source-format checks.

</tasks>

<must_haves>
- Walk/Crouch/Step intent is bounded and does not claim engine movement.
- Step validation rejects geometry outside the configured envelope.
- Stuck and invalidated states are explicit and deterministic.
</must_haves>

<verification>
1. Observe posture tests fail before implementation.
2. Run focused Core and complete portable/Metamod test suites.
3. Confirm no SDK dependency or export change.
</verification>
